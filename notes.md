# Заметки по Rust

## Установка Rust и Rustlings

На macOS и Linux Rust устанавливается через `rustup`:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

После установки нужно открыть новый терминал и проверить:

```bash
rustc --version
cargo --version
```

`rustc` — компилятор Rust: превращает файл `.rs` в программу. `cargo` запускает `rustc` и дополнительно умеет собирать проекты, запускать тесты и скачивать зависимости.

Установка Rustlings:

```bash
cargo install rustlings
```

Cargo скачает исходный код Rustlings, скомпилирует его с помощью `rustc` и установит готовую программу `rustlings`.

## 1. Модули, крейты и пространство имён

`std` — стандартная библиотека Rust. Это модуль, то есть пространство имён для связанного кода.

Запись `std::fs::read_to_string` означает: в `std` найти модуль `fs`, а в нём — функцию `read_to_string`.

`fs` — не класс. Это модуль для работы с файловой системой.

```rust
let text = std::fs::read_to_string("data.txt");
```

Крейт (`crate`) — единица компиляции в Rust: библиотека или программа, которую компилирует Rust.

### Область видимости и видимость модулей

Имя существует только в своей области видимости: от места объявления до конца блока `{ ... }`.

```rust
{
    let x = 5;
    println!("{x}");
}
// x здесь уже не существует
```

Элементы модуля по умолчанию приватны. `pub` делает элемент доступным снаружи модуля, а `pub use` экспортирует путь под новым именем.

```rust
mod snacks {
    mod fruits {
        pub const PEAR: &str = "Pear";
    }

    pub use self::fruits::PEAR as fruit;
}

println!("{}", snacks::fruit);
```

В путях `self` означает текущий модуль, `super` — родительский модуль, а `crate` — корень текущего крейта.

## Макросы

Макрос генерирует код во время компиляции. В отличие от функции, макрос может
принимать разное количество аргументов и работать с синтаксисом Rust. Макросы
вызываются с `!`:

```rust
my_macro!("hello");
```

Простейший декларативный макрос создают через `macro_rules!`:

```rust
macro_rules! my_macro {
    ($value:expr) => {
        println!("{}", $value);
    };
}

my_macro!(2 + 2); // напечатает 4
```

`$value:expr` означает «захватить выражение», а в правой части `$value`
подставляется в сгенерированный код. `macro_rules!` сопоставляет переданный
синтаксис с шаблоном и разворачивает подходящее правило.

## 2. Строки: `&str` и `String`

`"Привет"` — строковый литерал типа `&'static str`: неизменяемая ссылка на текст, записанный в бинарнике программы. Эти данные живут всё время работы программы.

`String` — владеющая строка. Её данные хранятся в куче, а на стеке находится дескриптор из трёх полей: указатель на данные, длина и вместимость.

```rust
let literal: &str = "Привет";
let text: String = "Привет".to_string();
```

`&str` заимствует уже существующий текст и не выделяет новую память. `String` создаёт или хранит собственные данные в куче.

`&str` сам не владеет текстом и не отвечает за его освобождение. Данные принадлежат владельцу, например `String`, или находятся в статической памяти программы:

```rust
let s = String::from("hello"); // s владеет данными
let part: &str = &s[0..2];      // part только заимствует "he"

let literal: &str = "hello";  // текст записан в бинарнике программы
```

Ссылка `&s`, где `s: String`, имеет тип `&String`: это одна ссылка на дескриптор `String`, а не `&&String`.

Функция, ожидающая `&str`, можно вызвать с `&String`: Rust автоматически применит deref coercion и приведёт `&String` к `&str`. Эти записи равнозначны:

```rust
let word = String::from("green");
is_a_color_word(&word);
is_a_color_word(word.as_str());
```

`char::to_uppercase()` возвращает итератор `Iterator<Item = char>`, а не сразу
один `char`: символ Unicode иногда преобразуется в несколько символов. Поэтому
для получения строки используют `collect::<String>()`.

```rust
let upper: String = 'a'.to_uppercase().collect();
```

`input.chars()` создаёт итератор `Chars` по символам строки. Метод `next()`
возвращает `Option<char>` и переводит итератор к следующему символу; исходная
строка при этом не изменяется:

```rust
let mut chars = "hello".chars();
chars.next();              // Some('h')
let rest = chars.as_str(); // "ello"
```

`as_str()` — специальный метод `Chars`, который возвращает ещё не прочитанную
часть строки. Переменная `chars` должна быть `mut`, потому что `next()` меняет
состояние итератора.

При переборе среза ссылок уровни ссылок сохраняются. Поэтому у `words: &[&str]`
обычный элемент цикла имеет тип `&&str`. Шаблон `for &word in words` убирает
внешнюю ссылку и даёт `word: &str`:

```rust
for &word in words {
    result.push(capitalize_first(word));
}
```

## `Option` и `Result`: общая идея

Оба типа описывают результат, который может отличаться от обычного значения, но причины разные:

```text
Option<T>   → Some(value) | None
Result<T,E> → Ok(value)   | Err(error)
```

`Option<T>` используют, когда значение может отсутствовать и отдельная причина не нужна: например, `HashMap::get` или `Vec::get`. `Result<T, E>` используют, когда операция может завершиться ошибкой и важно сообщить её причину: например, parsing или чтение файла.

## 3. `Result`: успех или ошибка

`Result<T, E>` — перечисление (`enum`) для операции, которая может завершиться успешно или с ошибкой:

```rust
Ok(T)  // успех, внутри значение типа T
Err(E) // ошибка, внутри значение типа E
```

`Ok(...)` не преобразует строку. Он создаёт успешный вариант `Result` и кладёт переданное значение внутрь.

`unwrap()` извлекает значение из `Ok`, но при `Err` вызывает `panic!`. Оператор
`?` при `Ok` также извлекает значение, а при `Err` сразу делает ранний
`return Err(...)` из текущей функции (при необходимости преобразуя тип ошибки):

```rust
let value = operation()?; // Ok(value) или ранний return Err(error)
```

```rust
let text: String = "Привет".to_string();
let result: Result<String, std::io::Error> = Ok(text);
```

Здесь `text` — строка, а `result` — успешный `Result` со строкой внутри. По смыслу это `Result::Ok(text)`, но обычно пишут коротко: `Ok(text)`.

`Result<String, String>` означает: при успехе функция возвращает `String`, а при ошибке — тоже строку с описанием ошибки:

```rust
fn generate_name(name: String) -> Result<String, String> {
    if name.is_empty() {
        Err(String::from("Имя не может быть пустым"))
    } else {
        Ok(format!("Привет, {name}!"))
    }
}
```

Если функция может вернуть ошибки разных типов, используют общий трейт `Error`:

```rust
use std::error::Error;

fn main() -> Result<(), Box<dyn Error>> {
    let number: i64 = "42".parse()?;
    println!("{number}");
    Ok(())
}
```

`dyn Error` означает «любой тип, реализующий `Error`», а `Box` хранит такой объект за одним общим типом.

Rust понимает, что `Ok` относится к `Result`, по ожидаемому типу, например по типу, который должна вернуть функция.

`Result` нужен, когда операция может как дать значение, так и не получиться. По варианту `Ok` или `Err` код выбирает, что делать дальше.

```rust
let result = std::fs::read_to_string("data.txt");

match result {
    Ok(text) => println!("Файл: {text}"),
    Err(error) => println!("Не удалось прочитать файл: {error}"),
}
```

`match result` проверяет, какой вариант `Result` лежит в переменной: `Ok` или `Err`. В `Ok(text)` имя `text` получает строку изнутри успешного результата; в `Err(error)` имя `error` получает ошибку.

## 4. Ошибки и их распространение

`std::io::Error` — структура (`struct`) с информацией об ошибке ввода-вывода, например «файл не найден». Это не класс.

Оператор `?` передаёт ошибку вызывающему коду. Если ошибки нет, он извлекает успешное значение.

```rust
fn read_data() -> Result<String, std::io::Error> {
    let text: String = std::fs::read_to_string("data.txt")?;
    Ok(text)
}
```

Вызов `std::fs::read_to_string("data.txt")` сначала возвращает `Result<String, std::io::Error>`. Затем `?` разбирает его: из `Ok(строка)` извлекает строку, а при `Err(error)` сразу завершает текущую функцию и возвращает `Err(error)`. Поэтому переменная `text` после `?` имеет тип `String`, а не `Result`.

В исходной сигнатуре `read_to_string` это записано короче: `-> std::io::Result<String>`. `std::io::Result<String>` — псевдоним для `Result<String, std::io::Error>`.

Строка с `?` почти равна такому коду:

```rust
let text: String = match std::fs::read_to_string("data.txt") {
    Ok(value) => value,
    Err(error) => return Err(error),
};
```

В ветке `Err(error)` переменная `error` уже содержит ошибку типа `std::io::Error`. Запись `Err(error)` не преобразует её: она создаёт значение `Result` с вариантом ошибки, чтобы функция могла вернуть ошибку вызывающему коду.

## 5. Преобразование строки в число

```rust
let guess: u32 = "42".parse().expect("Не число!");
```

`parse()` пытается превратить строку в число. `u32` задаёт нужный тип числа. `expect()` останавливает программу с указанным сообщением, если преобразование не удалось.

При арифметике типы не преобразуются автоматически. Например, `len()` возвращает
`usize`, поэтому перед делением на `f64` нужно явно преобразовать значение:

```rust
let total: f64 = 10.0;
let count: usize = 2;
let average = total / count as f64;
```

## 6. Владение, `move`, `Copy` и заимствование

Присваивание передаёт владение значением, если его тип не реализует `Copy`:

```rust
let s = String::from("hi");
let t = s; // владение String перешло в t
// println!("{s}"); // ошибка: s больше нельзя использовать
``` 

String — не ссылка, а владеющее значение. Внутри String есть: указатель на текст в куче + длина + вместимость. 

Если написать `let mut t = s;`, владение так же перейдёт в `t`, но строку через `t` можно будет менять:

```rust
let s = String::from("hi");
let mut t = s;
t.push_str("!"); // t == "hi!"
```

Типы `Copy` копируются, поэтому обе переменные остаются доступны. Обычно это простые данные фиксированного размера: `i32`, `bool`, `char`, `f64`, ссылки `&T`.

```rust
let x = 5;
let y = x; // копия
println!("{x}"); // работает
```

Заимствование передаёт ссылку, но не владение:

```rust
fn peek(s: &String) {}
fn take(s: String) {}

let s = String::from("hi");
peek(&s); // s остаётся доступной
take(s);  // владение передано функции
```

`&T` — безопасная ссылка на значение типа `T`. Ссылка не владеет данными и не освобождает их при выходе из области видимости.

`&u32` — ссылка на значение типа `u32`. Если `let x: u32 = 5`, то `&x` обычно указывает на значение на стеке. Но тип `&u32` не гарантирует место хранения: он может ссылаться и на поле данных в куче, и на статическую память. Для обычного `u32` часто проще передавать значение по копии, потому что `u32` реализует `Copy`.

При `for message in &messages` вектор заимствуется, а `message` имеет тип `&Message`. После цикла `messages` остаётся доступным. Запись `for message in messages` перемещает элементы из вектора, поэтому сам вектор после цикла использовать нельзя.

Изменять значение через ссылку можно только через изменяемую ссылку `&mut T` и оператор разыменования `*`:

```rust
let mut x: i32 = 5;
let r: &mut i32 = &mut x;
*r = 10; // меняем значение, на которое указывает r
```

`mut` перед `x` означает, что значение переменной можно менять. Поэтому из `x` можно создать изменяемую ссылку `&mut x`; у неизменяемой переменной это запрещено.

`let mut r` означало бы, что можно переназначить саму переменную `r` на другую ссылку. Для изменения значения через `*r` достаточно типа `&mut i32`; переменная `r` сама по себе меняться не должна.

`mut` в `mut vec: Vec<i32>` относится к переменной-параметру `vec`: её значение можно менять, например вызвать `vec.push(5)`. Тип остаётся `Vec<i32>`; записи `mut Vec<i32>` не бывает.

В `let y = &mut x` `&mut` относится к ссылке: `y` имеет тип `&mut i32` и через неё можно менять `x`. Но сама переменная `y` неизменяема и её нельзя переназначить. Запись `let mut y = &mut x` дополнительно разрешила бы переназначать `y` на другую ссылку.

Одновременно нельзя иметь две изменяемые ссылки на одно значение. Заимствования нужно завершать по очереди:

```rust
let mut x = Vec::new();

{
    let y = &mut x;
    y.push(42);
}

let z = &mut x;
z.push(13);
```

## 7. Умные указатели: `Box<T>`

`Box<T>` — владеющий указатель: само значение `Box` находится на стеке, а данные типа `T` — в куче. Когда `Box` уничтожается, Rust автоматически освобождает данные в куче.

```rust
let b = Box::new(5);
println!("{b}");
```

`b` имеет тип `Box<i32>`. Это не обычная ссылка `&i32`: `Box` владеет числом и отвечает за освобождение памяти, а `&i32` только временно заимствует уже существующее значение и не владеет им.

| | Обычная ссылка `&T` | `Box<T>` |
|---|---|---|
| Кто владеет данными? | Кто-то другой | Сам `Box` |
| Где лежат данные? | Там, где их создал владелец | В куче |
| Освобождает ли данные? | Нет | Да, при уничтожении `Box` |
| Создание | `&value` | `Box::new(value)` |

```rust
let x = String::from("hi");
let reference: &String = &x; // x владеет строкой, reference только смотрит

let boxed: Box<String> = Box::new(String::from("hi")); // boxed владеет строкой в куче
```

И `&T`, и `Box<T>` позволяют обратиться к `T` через разыменование, но смысл разный: ссылка берёт данные взаймы, а `Box` является их владельцем.

```rust
let x = 5;
let value_box: Box<i32> = Box::new(x);  // Box владеет копией числа
let reference_box: Box<&i32> = Box::new(&x); // Box владеет только ссылкой на x
```

`Box::new(x)` создаёт `Box<T>` и передаёт ему значение `x`. Для не-`Copy` типа, например `String`, это будет `move`, и исходная переменная станет недоступна. `Box::new(&x)` создаёт `Box<&T>`: исходным значением по-прежнему владеет `x`, а `Box` хранит ссылку на него и не может жить дольше `x`.

`Box::new(...)` называют упаковкой (`boxing`): значение помещается в кучу, а программа получает указатель фиксированного размера. Это полезно для больших данных и типов переменного размера.

`*b` разыменовывает `Box` — даёт доступ к значению внутри. Для `Copy`-типа будет создана копия, а для не-`Copy` типа владение можно извлечь из `Box`:

```rust
let b = Box::new(5);
let value = *b; // value == 5

let boxed = Box::new(String::from("hi"));
let text: String = *boxed; // String перемещена из Box
// boxed больше нельзя использовать
```

## `Rc<T>`: несколько владельцев в одном потоке

`Rc` (`Reference Counted`) позволяет нескольким значениям владеть одними
данными. `Rc::clone` не копирует объект, а увеличивает счётчик владельцев:

```rust
let sun = Rc::new(Sun);             // счётчик: 1
let earth = Rc::clone(&sun);        // счётчик: 2
println!("{}", Rc::strong_count(&sun)); // 2
drop(earth);                        // счётчик: 1
```

`Rc::new` — generic-конструктор. Упрощённо он определён так:

```rust
impl<T> Rc<T> {
    fn new(value: T) -> Rc<T> {
        // ...
    }
}
```

Из значения `Sun` Rust выводит `T = Sun`, поэтому `sun` имеет тип `Rc<Sun>`:

```rust
let sun: Rc<Sun> = Rc::new(Sun);
```

Когда счётчик становится равен нулю, данные освобождаются. `Rc` предназначен
для одного потока; для нескольких потоков используется `Arc`.

В упражнении все планеты должны клонировать один и тот же `sun`:

```rust
let saturn = Planet::Saturn(Rc::clone(&sun));
let uranus = Planet::Uranus(Rc::clone(&sun));
let neptune = Planet::Neptune(Rc::clone(&sun));
```

После `drop` планет нужно удалить также `jupiter`, `mars`, `earth`, `venus` и
`mercury`, чтобы счётчик вернулся к `1` — остался только `sun`.

## Потоки (`thread`)

Поток — отдельная параллельная ветка выполнения программы. `thread::spawn`
запускает поток и возвращает `JoinHandle` — объект, через который можно дождаться
завершения и получить результат:

```rust
let handle = thread::spawn(|| {
    2 + 2 // результат потока: 4
});

let result = handle.join().unwrap(); // ждём поток и получаем 4
```

`join()` блокирует текущий поток до завершения дочернего. Он возвращает
`Result`, потому что поток мог завершиться с паникой; `unwrap()` извлекает
успешный результат.

Упрощённо `JoinHandle<T>` можно представить так:

```rust
struct JoinHandle<T> { /* данные для управления потоком */ }

impl<T> JoinHandle<T> {
    fn join(self) -> Result<T, Box<dyn std::any::Any + Send>> {
        // ждёт завершения и возвращает результат потока
    }
}
```

`join()` принимает handle по значению, поэтому после ожидания этот handle
нельзя использовать повторно. `unwrap()` извлекает `T` из успешного `Result`;
при панике потока он сам вызовет `panic!`.

`unwrap()` не возвращает `Err`: он извлекает значение из `Ok`, а при `Err`
сам вызывает `panic!`. Для ручной обработки используют `match`:

```rust
match handle.join() {
    Ok(value) => println!("Результат: {value}"),
    Err(_) => println!("Поток завершился с паникой"),
}
```

`thread::spawn` начинает поток сразу. `handles.push(handle)` только сохраняет
`JoinHandle`; цикл не ждёт завершения. Ожидание происходит позже через
`handle.join()`, а порядок завершения потоков не гарантирован.

В упражнении результат каждого потока добавляется так:

```rust
for handle in handles {
    results.push(handle.join().unwrap());
}
```

## `Arc<T>`: общие данные между потоками

`Arc` (`Atomically Reference Counted`) — потокобезопасный счётчик ссылок.
Несколько `Arc` могут владеть одним значением:

```rust
let shared_numbers = Arc::new(numbers);
let child_numbers = Arc::clone(&shared_numbers);
```
`Arc::new(numbers)` перемещает `numbers` внутрь `Arc`, поэтому прежнее имя после
этого использовать нельзя.

`Arc::clone` не копирует весь `Vec`, а создаёт ещё один указатель на те же
данные и атомарно увеличивает счётчик владельцев. Это безопасно при работе
нескольких потоков.

Когда уничтожается последний `Arc`, счётчик становится равен нулю, и значение
автоматически освобождается. Для изменения общих данных используют, например,
`Arc<Mutex<T>>` или `Arc<RwLock<T>>`.

## `Mutex<T>`

`Mutex` — объект синхронизации, который разрешает доступ к данным только одному
потоку одновременно. Метод `lock()` блокирует поток до получения доступа и
возвращает временный `MutexGuard`:

```rust
let status = Arc::new(Mutex::new(JobStatus { jobs_done: 0 }));

let mut guard = status.lock().unwrap();
guard.jobs_done += 1;
// guard освобождает блокировку при выходе из области видимости
```

Для `let guard = mutex.lock().unwrap();` метод `lock()`:

1. пытается получить эксклюзивный доступ к данным внутри `Mutex`;
2. если доступ свободен — возвращает `MutexGuard`;
3. если другой поток уже владеет `MutexGuard` — ждёт;
4. через `guard` можно читать и изменять защищённый объект;
5. при уничтожении `guard` `Mutex` автоматически разблокируется.

`lock()` возвращает `Result`, потому что блокировка может стать «отравленной»
(`poisoned`), если другой поток запаниковал во время работы с данными. Поэтому
часто пишут:

```rust
let guard = mutex.lock().unwrap();
```

`unwrap()` извлекает `MutexGuard` из `Ok`, а при `Err` вызывает `panic!`.

`MutexGuard<T>` реализует `Deref<Target = T>`, поэтому Rust автоматически
разыменовывает guard при доступе к полю:

```rust
let guard = status.lock().unwrap();
guard.jobs_done; // компилятор понимает как (*guard).jobs_done
```

Для общего изменяемого состояния используют `Arc<Mutex<T>>`: `Arc` разделяет
владение, а `Mutex` защищает изменение данных.

`MutexGuard` освобождает блокировку автоматически при выходе из области
видимости:

```rust
{
    let mut guard = mutex.lock().unwrap();
    guard.value += 1;
} // guard уничтожен, Mutex разблокирован
```

`Mutex` — это объект, который разрешает доступ к защищённым данным только
одному потоку одновременно. Пока один поток владеет `MutexGuard`, другой поток
ждёт:

```rust
let guard = mutex.lock().unwrap();  // поток получил доступ
let guard2 = mutex.lock().unwrap(); // ждёт, пока guard будет уничтожен
```

## `Cow<T>`: копирование при записи

`Cow` (`Clone-On-Write`) может либо заимствовать данные, либо владеть ими.
Копия создаётся только при попытке изменить заимствованные данные через
`to_mut()`:

```rust
let values = vec![-1, 0, 1];
let mut data = Cow::from(&values); // Borrowed
data.to_mut()[0] = 1;              // клонирование, теперь Owned
```

`Cow::from(&vec)` сначала создаёт `Borrowed`; если изменений нет, копии не
будет. `Cow::from(vec)` сразу создаёт `Owned` и ничего дополнительно не копирует.

`to_mut()` действует так:

- если данные `Borrowed`, сначала клонирует их и превращает в `Owned`;
- если данные уже `Owned`, использует их напрямую без копирования.

`Cow` — это enum с вариантами `Borrowed(&B)` и `Owned(B::Owned)`. `B::Owned` —
ассоциированный тип трейта `ToOwned`, то есть владеющая версия `B`: для `str`
это `String`, а для `[i32]` — `Vec<i32>`. В выражении
`matches!(data, Cow::Borrowed(_))` проверяется вариант enum, а `_` означает,
что внутреннее значение неважно.

```rust
let text = String::from("hello");
let borrowed: Cow<str> = Cow::Borrowed(&text); // заимствованный &str
let owned: Cow<str> = Cow::Owned(String::from("hello")); // владеющий String
```

Упрощённо типы устроены так:

```rust
trait ToOwned {
    type Owned;
}

enum Cow<'a, B: ?Sized + ToOwned> {
    Borrowed(&'a B),
    Owned(B::Owned),
}
```

## 8. Трейты и `impl`

Трейт (`trait`) описывает общее поведение типов. `impl` создаёт методы типа или реализует трейт для типа.

Собственные методы для собственного типа — inherent `impl`:

```rust
impl<T> MyBox<T> {
    fn new(x: T) -> MyBox<T> {
        MyBox(x)
    }
}
```

Реализация трейта для типа — trait `impl`:

```rust
impl<T> std::ops::Deref for MyBox<T> {
    type Target = T;

    fn deref(&self) -> &T {
        &self.0
    }
}
```

В методе `&self` — короткая запись для `self: &Self`. `self` — текущий объект, а `Self` — тип, для которого написан этот `impl` или `trait`.

### `AsRef` и `AsMut`

`AsRef<T>` позволяет дёшево получить неизменяемую ссылку `&T`, а `AsMut<T>` —
изменяемую ссылку `&mut T`. Данные при этом не копируются.

```rust
fn byte_counter<T: AsRef<str>>(value: T) -> usize {
    value.as_ref().len()
}

fn double<T: AsMut<u32>>(value: &mut T) {
    let number = value.as_mut();
    *number *= 2;
}
```

`AsRef<str>` подходит для `&str` и `String`; `AsMut<u32>` позволяет изменить,
например, число внутри `Box<u32>`.

Если метод объявлен как `fn process(&mut self, ...)`, то внутри него `self` уже имеет тип `&mut Self`. Вызов `self.resize(width, height)` — короткая запись для `State::resize(self, width, height)`. Не нужно писать `&self`: это создало бы `&&mut Self`, а метод `resize` ожидает `&mut Self`.

```rust
match message {
    Message::Resize { width, height } => self.resize(width, height),
    Message::Move(point) => self.move_position(point),
    Message::Echo(text) => self.echo(text),
    Message::ChangeColor(red, green, blue) => {
        self.change_color(red, green, blue)
    }
    Message::Quit => self.quit(),
}
```

`match` выбирает ветку по варианту `enum` и извлекает его данные: например, `width` и `height` из `Message::Resize`.

Работает правило сиротства: можно реализовать свой трейт для чужого типа или чужой трейт для своего типа. Реализовать чужой трейт для чужого типа нельзя.

```rust
impl MyTrait for i32 {}       // свой трейт
impl std::fmt::Display for MyStruct {} // свой тип
// impl std::fmt::Display for i32 {}   // нельзя, так как оба не определены в текущем трейте. 
```

### `From` и `Into`

`From<A> for B` описывает, как создать `B` из `A`. Реализация `From` автоматически позволяет использовать обратную запись `into()`:

```rust
struct UserId(u32);

impl From<u32> for UserId {
    fn from(value: u32) -> Self {
        UserId(value)
    }
}

let id: UserId = 42u32.into();
```

Тип результата нужен Rust, чтобы понять, во что преобразовать значение. `into()` обычно используют для удобного преобразования типов.

`From` — гарантированное преобразование без ошибки:

```rust
fn from(value: T) -> Self
```

`FromStr` — попытка разобрать строку, которая может завершиться ошибкой:

```rust
fn from_str(s: &str) -> Result<Self, Self::Err>
```

После реализации `FromStr` работает запись:

```rust
let person: Person = "Mark,20".parse()?;
```

В цепочке:

```rust
let age = parts[1]
    .parse::<u8>()
    .map_err(ParsePersonError::ParseInt)?;
```

`parse()` возвращает `Result<u8, ParseIntError>`. `map_err` преобразует только
ошибку в `ParsePersonError::ParseInt`, а `?` извлекает успешное значение или
сразу возвращает ошибку из текущей функции.

## 9. Generics, `impl Trait` и trait objects

Ограничение `impl Trait` в параметре означает «некоторый конкретный тип, реализующий этот трейт»:

```rust
fn notify(item: &impl Summary) {}
```

Это почти то же самое, что generic-запись:

```rust
fn notify<T: Summary>(item: &T) {}
```

В параметре `impl Trait` — синтаксический сахар для generic-ограничения. При
нескольких параметрах есть важное отличие:

```rust
fn same<T: Summary>(a: &T, b: &T) {} // a и b одного типа
fn any(a: &impl Summary, b: &impl Summary) {} // типы могут различаться
```

`impl Trait` также используют для скрытия конкретного типа результата:

```rust
fn make_iter() -> impl Iterator<Item = char> { /* ... */ }
```

Здесь `impl Trait` применяется только в сигнатуре функции — для параметра или
возвращаемого значения. Отдельно `impl` используется для реализации методов
или трейта для типа:

```rust
impl User {
    fn name(&self) -> &str { "Alice" }
}

impl Summary for User { /* ... */ }
```

Сам тип объявляют через `struct`, `enum` или `type`, а не через `impl`.

Метод `collect` обобщён по типу результата:

```rust
fn collect<B>(self) -> B
where
    B: FromIterator<Self::Item>;
```

То есть `B` должен реализовывать `FromIterator` для элементов итератора. Для
сбора символов `String` имеет реализацию `FromIterator<char>`:

```rust
let text: String = ['H', 'i'].into_iter().collect();
let text = ['H', 'i'].into_iter().collect::<String>();
```

`::<String>` (turbofish) явно указывает generic-тип результата.

Упрощённо `collect` определён в трейте `Iterator` и делегирует сборку трейту
`FromIterator`:

```rust
trait Iterator {
    type Item; // типы элементов итератора 
            // укажем конкретный тип, например String, при реализации трейта 

    fn collect<B>(self) -> B // хотим, чтобы функция вернула тип B, который умеет получаться из итератора 
    where
        Self: Sized, // Sized - трейт, который говорит, что размер типа известен во время компиляции
        B: FromIterator<Self::Item>, // тип B реализует трейт FromIterator 
                                    // условно это означает: тип B умеет собираться из элементов итератора Self::Item
    {
        FromIterator::from_iter(self) // from_iter принимает итератор и возвращает нужное значение 
    }
}

//  Vec<i32> реализует трейт FromIterator<i32>, то есть умеет получаться из итератора 
trait FromIterator<A>: Sized { // любой тип, реализующий FromIterator<A>, 
                               // должен также реализовывать Sized 

    fn from_iter<T>(iter: T) -> Self // T - это любой тип с элементами типа A 
    where
        T: IntoIterator<Item = A>;  // который можно превратить в итератор  
                                    // (в том числе и сам интератор)

                                    // Item - это ассоциированный тип трейта IntoIterator
                                    // задается через type Item; 
}
``` 

Пример: 

```rust
// T = [i32; 3] T::Item = i32 
let source: [i32; 3] = [1, 2, 3]; 

// T можно превратить в итератор c элементами типа A = i32
let iterator : std::array::IntoIter<i32, 3> = source.into_iter(); 
// другой вариант 
let iterator : std::slice::Iter<'_, i32> = source.iter(); // into_iter() перемещает элементы, 
                                                            // а iter() выдаёт ссылки на них

// Vec собирает элементы этого итератора
let values: Vec<i32> = Vec::from_iter(iterator); 
```

Например, `Vec<T>` реализует `FromIterator<T>`, поэтому итератор можно собрать
в `Vec<T>`. `collect()` потребляет итератор.

`_` в типе — это placeholder: компилятор сам выводит конкретный тип:

```rust
let numbers: Vec<_> = (0..100u32).collect();
```

Это эквивалентно записи:

```rust
let numbers: Vec<u32> = (0..100u32).collect();
```

Несколько ограничений для одного параметра объединяются через `+`:

```rust
fn some_func(item: impl SomeTrait + OtherTrait) -> bool {
    item.some_function() && item.other_function()
}
```

Здесь `item` должен реализовывать и `SomeTrait`, и `OtherTrait`. 

------------- 

Пример. 

`self` — текущий экземпляр структуры. Вызов `card.print()` передаёт его в метод автоматически:

```rust
struct ReportCard<T> {
    grade: T,
    student_name: String,
}

impl<T: std::fmt::Display> ReportCard<T> {
    fn print(&self) -> String {
        format!("{}: {}", &self.student_name, &self.grade)
    }
}

let card = ReportCard {
    grade: 5.5,
    student_name: String::from("Alice"),
};
let text = card.print(); // внутри метода self — ссылка на card
``` 

`&self` только читает объект и не забирает владение. `&mut self` позволяет менять его поля, а `self` без `&` забирает объект целиком. 

При методе `fn print(&self)` ссылки вроде `&self.student_name` не дают переместить поле `String` из объекта:

```rust
format!("{}", &self.student_name);
```

`format!` обычно сам заимствует аргументы, поэтому `&` можно опустить, но явная ссылка подчёркивает, что владение не передаётся. 

--------- 

`dyn Trait` — trait object: конкретный тип можно не знать заранее. Вызов метода выбирается во время выполнения (динамическая диспетчеризация).

```rust
fn notify(item: &dyn Summary) {}
```

Generic-параметр `T` может быть любым типом, в том числе ссылкой. Например, для `Wrapper::new("Foo")` Rust выводит `T = &str`, поэтому получается `Wrapper<&str>`.

Разница между вариантами параметров:

```rust
fn by_value(value: impl Licensed) {}
fn by_reference(value: &impl Licensed) {}
fn dynamic(value: &dyn Licensed) {}
```

`impl Licensed` принимает владеющее значение и использует статическую диспетчеризацию. `&impl Licensed` заимствует значение, но тоже использует статическую диспетчеризацию. `&dyn Licensed` заимствует значение и выбирает реализацию во время выполнения.

Unit-like struct не имеет полей, поэтому его имя сразу создаёт значение:

```rust
struct SomeSoftware;
let software = SomeSoftware;
```

Поэтому вызов `compare_license_types(SomeSoftware, OtherSoftware)` создаёт и передаёт два пустых значения структур.

Например, `Vec<Box<dyn Summary>>` может хранить разные типы, реализующие `Summary`. Указатель на `dyn Summary` содержит адрес данных и адрес таблицы методов (`vtable`), поэтому вызов `item.summarize()` знает, какую реализацию вызвать.

## 10. Замыкания и трейты `Fn`

Замыкание — функция, которая может захватить переменные из внешнего окружения:

```rust
let n = 10;
let add_n = |x| x + n;
println!("{}", add_n(5)); // 15
```

Компилятор создаёт для каждого замыкания анонимный тип и реализует для него один или несколько трейтов: `Fn`, `FnMut`, `FnOnce`.

```rust
fn call_it<F: Fn(String) -> String>(f: F) {}
fn call_it(f: impl Fn(String) -> String) {}
```

Эти записи означают одно: параметр `f` — некоторый тип, который можно вызвать с `String` и получить `String`.

`Fn` только читает захваченное окружение; `FnMut` может его менять; `FnOnce` забирает захваченное значение и может быть вызван только один раз.

```rust
let s = String::from("hi");
let f = || println!("{s}"); // Fn

let mut count = 0;
let mut g = || count += 1; // FnMut
g();

let s = String::from("hi");
let h = move || drop(s); // FnOnce
h();
```

`g` объявлено с `mut`, потому что вызов `g()` меняет захваченное `count`. У трейта `FnMut` метод вызова принимает замыкание как `&mut self`, поэтому вызывать такое замыкание можно только через изменяемую переменную.

Любое замыкание `Fn` также подходит там, где нужен `FnMut` или `FnOnce`; любое `FnMut` подходит там, где нужен `FnOnce`.

`move` у замыкания определяет, что захваченные значения передаются внутрь замыкания по владению. `mut` перед именем переменной делает возможным изменяемый вызов замыкания.

## 11. `Option<T>`

`Option<T>` — перечисление для значения, которое может отсутствовать. Это безопасная замена `null`:

```rust
enum Option<T> {
    Some(T),
    None,
}

let x: Option<String> = Some("hi".to_string());

match x {
    Some(text) => println!("Есть: {text}"),
    None => println!("Ничего нет"),
}
```

Компилятор требует обработать оба варианта: `Some(T)` и `None`.

`let ... else` извлекает значение, только если оно совпадает с образцом. В `else` нужно завершить текущий путь выполнения через `panic!`, `return`, `break` или `continue`:

```rust
let Some(amount) = basket.get(&fruit_kind) else {
    panic!("Fruit kind {fruit_kind:?} was not found in basket");
};
```

Если `get` вернул `Some(amount)`, создаётся переменная `amount`. Если вернулся `None`, выполняется `else`.

`ref` не является частью определения `Option`; это способ связать значение в pattern matching по ссылке, не перемещая его:

```rust
match optional_point {
    Some(ref point) => println!("{}, {}", point.x, point.y),
    None => panic!("No match!"),
}
```

Здесь `point` имеет тип `&Point`. 
Более современная альтернатива — заимствовать весь `Option` перед `match`:

```rust
match &optional_point {
    Some(point) => println!("{}, {}", point.x, point.y),
    None => panic!("No match!"),
}
```

## 12. Времена жизни

Время жизни показывает, как долго действительна ссылка. Аннотация не продлевает жизнь данных: она только описывает связь между ссылками.

`'a`, `'b` и `'c` — произвольные имена времён жизни, а не переменные. Например, функция возвращает первую ссылку и связывает её время жизни с `'a`:

```rust
fn first<'a, 'b>(first: &'a str, _second: &'b str) -> &'a str {
    first
}
```

Локальная переменная обычно живёт короче аргумента функции. Нельзя вернуть ссылку с долгим временем жизни `'a` на такую короткоживущую переменную `'b`.

Если функция возвращает одну из двух входных ссылок, их связь указывают общей аннотацией:

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

Результат живёт не дольше, чем более короткоживущая из входных ссылок. `'a` не продлевает жизнь данных, а только описывает эту связь.

```rust
fn as_str<'a>(data: &'a u32) -> &'a str {
    let s = format!("{}", data);
    // &s // нельзя вернуть: s будет уничтожена в конце функции
    todo!()
}
```

`data` имеет тип `&u32`, а `format!("{}", data)` создаёт новую строку типа `String`. `&s` — ссылка на эту строку; Rust может привести `&String` к `&str`. Функция обещала вернуть ссылку, живущую не меньше, чем `data`, но локальная строка `s` живёт только до конца функции. Короткое время жизни нельзя «повысить» до более длинного.

`'static` означает, что ссылка действительна всё время работы программы. Строковые литералы имеют тип `&'static str`. 

Еще один пример со структурами. 'a - это контракт, который говорит: Book<'a> содержит ссылки, действительные как минимум в течение 'a

```rust
struct Book<'a> {
      author: &'a str,
      title: &'a str,
  }
``` 

Это позволяет Rust корректно проверять функции:
```rust
fn make_book<'a>(author: &'a str, title: &'a str) -> Book<'a> {
    Book { author, title }
}
``` 
Без 'a Rust не смог бы описать, сколько живут ссылки внутри Book, и не допустил бы такую структуру. Это нужно Rust, чтобы он при компиляции мог прогнать все свои проверки. 

Даже если ссылки &author и &title имеют в реальности разное время жизни, но если в функции указано 'a для обеих ссылок, то выберется наименьшее lifetime. 

## 13. `RefCell<T>`

Обычные правила заимствования Rust проверяются во время компиляции. `RefCell<T>` переносит проверку на время выполнения.

```rust
use std::cell::RefCell;

let value = RefCell::new(5);
let read = value.borrow();       // Ref<T>, похоже на &T
drop(read);
let mut write = value.borrow_mut(); // RefMut<T>, похоже на &mut T
*write += 1;
```

Если одновременно нарушить правила заимствования, программа запаникует во время выполнения, а не выдаст ошибку компиляции.

## 14. Clap: разбор аргументов командной строки

`clap` — библиотека для разбора аргументов командной строки. Трейт `Parser` и `#[derive(Parser)]` создают код разбора по описанию структуры.

```rust
use clap::Parser;

#[derive(Parser)]
struct Cli {
    #[arg(short, long)]
    arg: String,
    #[arg(short, long)]
    optional_arg: Option<String>,
}

fn main() {
    let args = Cli::parse();
    println!("Аргумент: {}", args.arg);
}
```

Запуск `program --arg value` заполнит поле `arg`. Необязательный аргумент обычно имеет тип `Option<T>`.

## 15. `HashMap` и перебор ключей

При переборе массива по значению переменная получает само значение:

```rust
for fruit in fruit_kinds {
    // fruit: Fruit
}
```

При `for fruit in &fruit_kinds` переменная имела бы тип `&Fruit`. В задаче `fruit` берётся из массива, а `basket` — отдельная изменяемая ссылка типа `&mut HashMap<Fruit, u32>`.

`contains_key(&fruit)` только проверяет ключ и поэтому заимствует его. `insert(fruit, 1)` сохраняет ключ в `HashMap` и забирает владение им.

```rust
if !basket.contains_key(&fruit) {
    basket.insert(fruit, 1);
}
```

`scores.get_mut(...)` возвращает `Option<&mut TeamScores>`. При деструктурировании поля имеют тип `&mut u8`, поэтому их нужно явно разыменовать:

```rust
*goals_scored += team_1_score;
```

Если сохранить ссылку целиком как `team: &mut TeamScores`, Rust автоматически разыменует её при доступе к полю:

```rust
team.goals_scored += team_1_score;
// примерно то же, что: (*team).goals_scored += team_1_score;
```
