# Заметки по Rust

## Установка Rust и Rustlings

На macOS и Linux Rust устанавливается через `rustup`:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

После установки нужно открыть новый терминал и проверить:

```bash
rustc --version
cargo --version
```

`rustc` — компилятор Rust: превращает файл `.rs` в программу. `cargo` запускает `rustc` и дополнительно умеет собирать проекты, запускать тесты и скачивать зависимости.

Установка Rustlings:

```bash
cargo install rustlings
```

Cargo скачает исходный код Rustlings, скомпилирует его с помощью `rustc` и установит готовую программу `rustlings`.

## 1. Модули, крейты и пространство имён

`std` — стандартная библиотека Rust. Это модуль, то есть пространство имён для связанного кода.

Запись `std::fs::read_to_string` означает: в `std` найти модуль `fs`, а в нём — функцию `read_to_string`.

`fs` — не класс. Это модуль для работы с файловой системой.

```rust
let text = std::fs::read_to_string("data.txt");
```

Крейт (`crate`) — единица компиляции в Rust: библиотека или программа, которую компилирует Rust.

## 2. Строки: `&str` и `String`

`"Привет"` — строковый литерал типа `&'static str`: неизменяемая ссылка на текст, записанный в бинарнике программы. Эти данные живут всё время работы программы.

`String` — владеющая строка. Её данные хранятся в куче, а на стеке находится дескриптор из трёх полей: указатель на данные, длина и вместимость.

```rust
let literal: &str = "Привет";
let text: String = "Привет".to_string();
```

`&str` заимствует уже существующий текст и не выделяет новую память. `String` создаёт или хранит собственные данные в куче.

Ссылка `&s`, где `s: String`, имеет тип `&String`: это одна ссылка на дескриптор `String`, а не `&&String`.

## 3. `Result`: успех или ошибка

`Result<T, E>` — перечисление (`enum`) для операции, которая может завершиться успешно или с ошибкой:

```rust
Ok(T)  // успех, внутри значение типа T
Err(E) // ошибка, внутри значение типа E
```

`Ok(...)` не преобразует строку. Он создаёт успешный вариант `Result` и кладёт переданное значение внутрь.

```rust
let text: String = "Привет".to_string();
let result: Result<String, std::io::Error> = Ok(text);
```

Здесь `text` — строка, а `result` — успешный `Result` со строкой внутри. По смыслу это `Result::Ok(text)`, но обычно пишут коротко: `Ok(text)`.

Rust понимает, что `Ok` относится к `Result`, по ожидаемому типу, например по типу, который должна вернуть функция.

`Result` нужен, когда операция может как дать значение, так и не получиться. По варианту `Ok` или `Err` код выбирает, что делать дальше.

```rust
let result = std::fs::read_to_string("data.txt");

match result {
    Ok(text) => println!("Файл: {text}"),
    Err(error) => println!("Не удалось прочитать файл: {error}"),
}
```

`match result` проверяет, какой вариант `Result` лежит в переменной: `Ok` или `Err`. В `Ok(text)` имя `text` получает строку изнутри успешного результата; в `Err(error)` имя `error` получает ошибку.

## 4. Ошибки и их распространение

`std::io::Error` — структура (`struct`) с информацией об ошибке ввода-вывода, например «файл не найден». Это не класс.

Оператор `?` передаёт ошибку вызывающему коду. Если ошибки нет, он извлекает успешное значение.

```rust
fn read_data() -> Result<String, std::io::Error> {
    let text: String = std::fs::read_to_string("data.txt")?;
    Ok(text)
}
```

Вызов `std::fs::read_to_string("data.txt")` сначала возвращает `Result<String, std::io::Error>`. Затем `?` разбирает его: из `Ok(строка)` извлекает строку, а при `Err(error)` сразу завершает текущую функцию и возвращает `Err(error)`. Поэтому переменная `text` после `?` имеет тип `String`, а не `Result`.

В исходной сигнатуре `read_to_string` это записано короче: `-> std::io::Result<String>`. `std::io::Result<String>` — псевдоним для `Result<String, std::io::Error>`.

Строка с `?` почти равна такому коду:

```rust
let text: String = match std::fs::read_to_string("data.txt") {
    Ok(value) => value,
    Err(error) => return Err(error),
};
```

В ветке `Err(error)` переменная `error` уже содержит ошибку типа `std::io::Error`. Запись `Err(error)` не преобразует её: она создаёт значение `Result` с вариантом ошибки, чтобы функция могла вернуть ошибку вызывающему коду.

## 5. Преобразование строки в число

```rust
let guess: u32 = "42".parse().expect("Не число!");
```

`parse()` пытается превратить строку в число. `u32` задаёт нужный тип числа. `expect()` останавливает программу с указанным сообщением, если преобразование не удалось.

## 6. Владение, `move`, `Copy` и заимствование

Присваивание передаёт владение значением, если его тип не реализует `Copy`:

```rust
let s = String::from("hi");
let t = s; // владение String перешло в t
// println!("{s}"); // ошибка: s больше нельзя использовать
```

Если написать `let mut t = s;`, владение так же перейдёт в `t`, но строку через `t` можно будет менять:

```rust
let s = String::from("hi");
let mut t = s;
t.push_str("!"); // t == "hi!"
```

Типы `Copy` копируются, поэтому обе переменные остаются доступны. Обычно это простые данные фиксированного размера: `i32`, `bool`, `char`, `f64`, ссылки `&T`.

```rust
let x = 5;
let y = x; // копия
println!("{x}"); // работает
```

Заимствование передаёт ссылку, но не владение:

```rust
fn peek(s: &String) {}
fn take(s: String) {}

let s = String::from("hi");
peek(&s); // s остаётся доступной
take(s);  // владение передано функции
```

`&T` — безопасная ссылка на значение типа `T`. Ссылка не владеет данными и не освобождает их при выходе из области видимости.

Изменять значение через ссылку можно только через изменяемую ссылку `&mut T` и оператор разыменования `*`:

```rust
let mut x: i32 = 5;
let r: &mut i32 = &mut x;
*r = 10; // меняем значение, на которое указывает r
```

`mut` перед `x` означает, что значение переменной можно менять. Поэтому из `x` можно создать изменяемую ссылку `&mut x`; у неизменяемой переменной это запрещено.

`let mut r` означало бы, что можно переназначить саму переменную `r` на другую ссылку. Для изменения значения через `*r` достаточно типа `&mut i32`; переменная `r` сама по себе меняться не должна.

## 7. Умные указатели: `Box<T>`

`Box<T>` — владеющий указатель: само значение `Box` находится на стеке, а данные типа `T` — в куче. Когда `Box` уничтожается, Rust автоматически освобождает данные в куче.

```rust
let b = Box::new(5);
println!("{b}");
```

`Box::new(...)` называют упаковкой (`boxing`): значение помещается в кучу, а программа получает указатель фиксированного размера. Это полезно для больших данных и типов переменного размера.

`*b` разыменовывает `Box` — даёт доступ к значению внутри. Для `Copy`-типа будет создана копия, а для не-`Copy` типа владение можно извлечь из `Box`:

```rust
let b = Box::new(5);
let value = *b; // value == 5

let boxed = Box::new(String::from("hi"));
let text: String = *boxed; // String перемещена из Box
```

## 8. Трейты и `impl`

Трейт (`trait`) описывает общее поведение типов. `impl` создаёт методы типа или реализует трейт для типа.

Собственные методы для собственного типа — inherent `impl`:

```rust
impl<T> MyBox<T> {
    fn new(x: T) -> MyBox<T> {
        MyBox(x)
    }
}
```

Реализация трейта для типа — trait `impl`:

```rust
impl<T> std::ops::Deref for MyBox<T> {
    type Target = T;

    fn deref(&self) -> &T {
        &self.0
    }
}
```

Работает правило сиротства: можно реализовать свой трейт для чужого типа или чужой трейт для своего типа. Реализовать чужой трейт для чужого типа нельзя.

```rust
impl MyTrait for i32 {}       // свой трейт
impl std::fmt::Display for MyStruct {} // свой тип
// impl std::fmt::Display for i32 {}   // нельзя, так как оба не определены в текущем трейте. 
```

## 9. Generics, `impl Trait` и trait objects

Ограничение `impl Trait` в параметре означает «некоторый конкретный тип, реализующий этот трейт»:

```rust
fn notify(item: &impl Summary) {}
```

Это почти то же самое, что generic-запись:

```rust
fn notify<T: Summary>(item: &T) {}
```

Конкретный тип выбирается при компиляции (статическая диспетчеризация).

`dyn Trait` — trait object: конкретный тип можно не знать заранее. Вызов метода выбирается во время выполнения (динамическая диспетчеризация).

```rust
fn notify(item: &dyn Summary) {}
```

Например, `Vec<Box<dyn Summary>>` может хранить разные типы, реализующие `Summary`. Указатель на `dyn Summary` содержит адрес данных и адрес таблицы методов (`vtable`), поэтому вызов `item.summarize()` знает, какую реализацию вызвать.

## 10. Замыкания и трейты `Fn`

Замыкание — функция, которая может захватить переменные из внешнего окружения:

```rust
let n = 10;
let add_n = |x| x + n;
println!("{}", add_n(5)); // 15
```

Компилятор создаёт для каждого замыкания анонимный тип и реализует для него один или несколько трейтов: `Fn`, `FnMut`, `FnOnce`.

```rust
fn call_it<F: Fn(String) -> String>(f: F) {}
fn call_it(f: impl Fn(String) -> String) {}
```

Эти записи означают одно: параметр `f` — некоторый тип, который можно вызвать с `String` и получить `String`.

`Fn` только читает захваченное окружение; `FnMut` может его менять; `FnOnce` забирает захваченное значение и может быть вызван только один раз.

```rust
let s = String::from("hi");
let f = || println!("{s}"); // Fn

let mut count = 0;
let mut g = || count += 1; // FnMut
g();

let s = String::from("hi");
let h = move || drop(s); // FnOnce
h();
```

`g` объявлено с `mut`, потому что вызов `g()` меняет захваченное `count`. У трейта `FnMut` метод вызова принимает замыкание как `&mut self`, поэтому вызывать такое замыкание можно только через изменяемую переменную.

Любое замыкание `Fn` также подходит там, где нужен `FnMut` или `FnOnce`; любое `FnMut` подходит там, где нужен `FnOnce`.

`move` у замыкания определяет, что захваченные значения передаются внутрь замыкания по владению. `mut` перед именем переменной делает возможным изменяемый вызов замыкания.

## 11. `Option<T>`

`Option<T>` — перечисление для значения, которое может отсутствовать. Это безопасная замена `null`:

```rust
enum Option<T> {
    Some(T),
    None,
}

let x: Option<String> = Some("hi".to_string());

match x {
    Some(text) => println!("Есть: {text}"),
    None => println!("Ничего нет"),
}
```

Компилятор требует обработать оба варианта: `Some(T)` и `None`.

## 12. Времена жизни

Время жизни показывает, как долго действительна ссылка. Аннотация не продлевает жизнь данных: она только описывает связь между ссылками.

```rust
fn as_str<'a>(data: &'a u32) -> &'a str {
    let s = format!("{}", data);
    // &s // нельзя вернуть: s будет уничтожена в конце функции
    todo!()
}
```

`data` имеет тип `&u32`, а `format!("{}", data)` создаёт новую строку типа `String`. `&s` — ссылка на эту строку; Rust может привести `&String` к `&str`. Функция обещала вернуть ссылку, живущую не меньше, чем `data`, но локальная строка `s` живёт только до конца функции. Короткое время жизни нельзя «повысить» до более длинного.

`'static` означает, что ссылка действительна всё время работы программы. Строковые литералы имеют тип `&'static str`.

## 13. `RefCell<T>`

Обычные правила заимствования Rust проверяются во время компиляции. `RefCell<T>` переносит проверку на время выполнения.

```rust
use std::cell::RefCell;

let value = RefCell::new(5);
let read = value.borrow();       // Ref<T>, похоже на &T
drop(read);
let mut write = value.borrow_mut(); // RefMut<T>, похоже на &mut T
*write += 1;
```

Если одновременно нарушить правила заимствования, программа запаникует во время выполнения, а не выдаст ошибку компиляции.

## 14. Clap: разбор аргументов командной строки

`clap` — библиотека для разбора аргументов командной строки. Трейт `Parser` и `#[derive(Parser)]` создают код разбора по описанию структуры.

```rust
use clap::Parser;

#[derive(Parser)]
struct Cli {
    #[arg(short, long)]
    arg: String,
    #[arg(short, long)]
    optional_arg: Option<String>,
}

fn main() {
    let args = Cli::parse();
    println!("Аргумент: {}", args.arg);
}
```

Запуск `program --arg value` заполнит поле `arg`. Необязательный аргумент обычно имеет тип `Option<T>`.

## 15. Работа с Rustlings for HSE

Решай упражнения по порядку, проверяй их командой из README репозитория и сохраняй изменения коммитами.

```bash
git add exercises/01_variables/variables1.rs
git commit -m "Solve variables1"
git push -u origin solutions
```

Проверка GitHub Actions запускается для pull request из `ifde/rustlings-for-hse:solutions` в `Kumokage/rustlings-for-hse:master`.

После установки Rust и Rustlings можно проверить одно упражнение командой:

```bash
rustlings run variables1
```

Проверить все упражнения:

```bash
rustlings check-all
```

`rustlings-for-hse` — отдельный Git-репозиторий внутри папки с материалами. Внешний репозиторий специально игнорирует его через `.gitignore`. Чтобы увидеть его изменения в VS Code, открой именно папку `rustlings-for-hse` как отдельную рабочую папку или выбери команду `Git: Open Repository`.
